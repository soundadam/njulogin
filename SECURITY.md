# Security policy

## Reporting

Use GitHub's private **Report a vulnerability** flow after the repository is
published. Before publication, report privately to the repository owner.

Private vulnerability reporting must be enabled and verified before repository
visibility becomes public. Until then, the owner remains the private reporting
channel; do not open a public issue for a suspected vulnerability.

Do not include passwords, local credential-file contents, Cookies, QR URLs,
session identifiers, raw portal responses, MAC addresses, or IP addresses in a
report.

## Supported versions

No released version exists yet. Security support begins with the first tagged
release after the gates in `docs/release-readiness.md` pass.
